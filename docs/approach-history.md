# Approach history

## Live team identity and launch records

Herdr owns live names, pane IDs and delivery. The launch record captures the workspace and ordered roots so Doctor can check an existing team. This approach remains in use. Its acceptance condition is a match between the recorded scope and the live processes. The implementation and its checks are in [run-state.sh](../scripts/lib/run-state.sh) and [test.sh](../scripts/test.sh). Results of the original implementation run are unknown. The design before conversation linking is preserved at commit `eddf246` in `docs/launch-state.md` and `docs/omx-comparison.md`. [Launch state](launch-state.md) and [the OMX comparison](omx-comparison.md) record the decision to keep messages and workflow state with their existing owners.

## Resume the peers of a selected Planner conversation

The live team name can survive a change of Codex conversation. Link the three Codex thread IDs at managed launch and use the Planner ID to select the two peers in the same team and project scope. Acceptance requires both peer panes to switch to their recorded IDs and handoffs to stop when a link is missing or a switch is incomplete. See [the bridge](../scripts/herdr_mcp.py) and [its regression tests](../tests/test_herdr_mcp.py). A local Herdr 0.8.2 / Codex CLI 0.160.1 exercise restored two groups in both directions by selecting only the Planner. The earlier group came from a closed workspace. A freshly named group with unused peer chats could also be reopened. The static suite passed, and the live communication test received the expected Coder and Reviewer replies with a test-only GPT-6.1 model override. After upgrading the standalone CLI to 0.171.0, the same live test recovered a 0.160.1 group and then the new group. Both handoffs passed with Planner and Reviewer on GPT-6.2 Astra and Coder on GPT-6.2 Sol, all at xhigh. The checks were `./scripts/test.sh static` and `./scripts/test.sh --team link-test communication`. Revisit this approach if Codex changes how it reports the active thread or accepts a resume command.

## Native CLI selection per role

Keep one native interactive client per role. The launch record identifies each CLI, and the conversation index qualifies Claude and Antigravity IDs by provider. Existing Codex IDs keep their original keys. Claude reports the current ID through its Herdr SessionStart hook. Antigravity publishes its active conversation ID as the terminal title, including when the user changes chats between model turns. The launcher names fresh chats with a native slash command and checks the saved title before binding. This avoids spending model quota to initialize a team.

Acceptance requires the selected CLI and role policy in each pane, exact peer IDs after selecting either of two groups, and rejection of an unknown Planner or a peer owned by another CLI. The bridge tests exercise all 27 role assignments and switch in both directions. The previous Codex-only results above continue to cover older records. Revisit if a CLI changes its session identity events, in-pane resume syntax, or role-policy flags. [Bridge tests](../tests/test_herdr_mcp.py) · [Native role configuration](../scripts/providers.py)

On this Mac, Herdr 0.8.2 restored two Claude Code Planner groups in both directions, including a previously closed workspace, with a Codex 0.171.0 Coder and a Claude Reviewer. All three native session IDs matched each selection. Opening the running team again without CLI flags passed Doctor and reused the same three panes. Claude Code reported 2.1.328 during initial inspection and 2.1.330 after its native update. Fresh Claude chats named with `/rename` were recoverable before any model turn. The CLI argument checks cover all six Claude/Antigravity role configurations. Antigravity 1.5.15 exposed the live UUID in the Herdr terminal title. After its first-run setup, Claude Planner, Codex Coder and Gemini Reviewer recovered two groups in both directions. Gemini Reviewer returned the requested communication-test token. Antigravity starts MCP on its first model turn, so its Planner needs an observer at launch to follow a picker selection before any turn. With that observer, an Antigravity Planner also restored its Claude Coder and Codex Reviewer in both directions.

## Shared SSH destination for local teams

Record the verified SSH host, optional port and physical remote directory against the linked Planner conversation. Workers resolve the destination through their live pane and linked native session IDs. The handoff bridge includes the destination in the prompt. Local OpenSSH owns host verification, authentication and transport. Read-only roles can inspect files and Git state. Only Coder gets remote shell execution. The Planner can clear the binding to resume local work.

Acceptance requires all three native clients to resolve the same directory, a Reviewer to read Coder output over SSH, and a switched group to recover only its own destination. Bridge tests cover group switches and role restrictions. An isolated OpenSSH server accepted all three roles, Codex Coder wrote a disposable file and Gemini Reviewer read its contents. A separate read-only check on the user-selected device returned the same login directory through Claude Planner, Codex Coder and Gemini Reviewer. Claude's configured model endpoint returned a quota error during its model-driven check. The SSH transport and the Claude role endpoint were checked independently. Revisit if OpenSSH authentication, role permissions or a provider's MCP dispatch changes. [SSH bridge and runtime](../scripts/herdr_mcp.py) · [Verification](../tests/test_herdr_mcp.py)

## Provider-specific skill loading

Codex embeds Stop That Shit in its installed profile. Claude Code and Antigravity use the shared role prompt. A Claude session denies the plugin skill by name to cover machines where it is already installed. Antigravity 1.5.15 persisted the old agent instructions in an early test chat. Changing its agent file and resuming the same ID still sent those instructions on the next model turn. The native agent switch forks that history. The bridge checks the saved Gemini role before linking or handing off. Chats created with the current role prompts can resume in place. Revisit if Antigravity changes its snapshot format or provides in-place policy updates. Its SSH tool returned the R7 login directory and the review passed. All three role endpoints independently returned the same directory. ## Local shortcut and switching CLI in a role pane

Reuse the existing right/down half splits and role argument builder. A project-specific Herdr session opens from the working directory. The conversation group owns the SSH destination and retains a native conversation per role and CLI. Accept when the shortcut starts three Codex roles, repeated attachment preserves their panes, workers can switch independently, and switching back restores each native ID.

A directly executed replacement CLI left Herdr's interactive readiness unset. Starting the replacement through Herdr's managed `agent start` restored the live identity and readiness used by the bridge. Early simultaneous resume requests from the observer and switch command were concatenated in Codex. Both paths now coordinate on the team's switch lock. Revisit direct execution only if Herdr starts reporting equivalent managed readiness for these processes.

Verified on macOS with Herdr 0.8.2. A fresh project had one full-height Planner on the left and equal-width Coder and Reviewer panes stacked on the right. Reattaching retained the same workspace, pane IDs, and three Codex IDs. Planner and Coder switched to Claude Code and Reviewer to Antigravity. All three recovered their exact original conversation IDs on switching back. The static suite also checked the shared SSH destination after changing the Planner and Coder CLIs. Revisit if Herdr changes its managed launch or a supported CLI changes its resume UI. ## Herdr 0.9.5 compatibility

The macOS upgrade retained the native role layout, group registry and SSH bridge. Herdr can return `agent_not_ready` while the newly launched Codex pane waits for folder trust. The launcher leaves the decision with the user, waits on the existing managed agent, and verifies its identity and permissions. Explicit CLI switches briefly saw the old name registered on the same pane after the previous client exited. The bounded retry covers that pane only. Codex's model notice counters and the user's folder trust records now coexist with the installed policy digest. Changes to permission fields still fail the integrity check.

With Herdr 0.9.5 and Codex CLI 0.171.0, a new project started three Codex agents and a second attachment retained the workspace, panes and chat IDs. Planner and Coder switched to Claude Code and Reviewer to Antigravity. All three role endpoints independently read the same R7 login directory, both in the mixed team and with three Codex agents. Switching back recovered the exact three Codex conversation IDs. Selecting either of two linked Planner chats also restored both matching worker IDs.

A live review exposed a separate timing problem. Herdr returned a settled state before the Reviewer completed, and a scrolled Codex viewport omitted the reply header. For Codex 0.171+ with a local rollout, the bridge now matches the exact submitted prompt and waits for that turn’s completion, then rechecks the live role, pane and conversation. Clients without that event format retain the terminal path. The full workflow test checks each role’s original reply and the independent fixture diff and tests. On this Mac the Coder changed only `calculator.py`, the Reviewer passed round one, and the Planner approved the result. Revisit if Herdr changes its state reporting or Codex changes its native event or profile formats.
